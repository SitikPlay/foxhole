## [1.2.0] — 2026-10-26

### Добавлено
- Уровни доступа для каждого приложения:
  - **READ** — только безобидное чтение: `ping`, `getsetting`;
  - **PERMISSIONS** — плюс `grant`, `revoke`, `appop`, `putsetting`;
  - **FULL** — любые shell-команды (как раньше).
  Проверка выполняется в провайдере до отправки на сервер. Алиасы узнаются по первому
  слову; всё нераспознанное, а также команды с разделителями, подстановками и
  конвейерами считаются FULL — обходы вида `getsetting global x; rm -rf /` не проходят.
  Уровень выбирается в диалоге выдачи доступа (по умолчанию READ) и меняется позже без
  отзыва; ранее выданные доступы после обновления остаются FULL (миграция).
- Уведомление о новом запросе доступа: название приложения берётся из PackageManager,
  кнопки «Разрешить (READ)» и «Отклонить», тап открывает список ожидающих. Одно
  уведомление на uid, после решения (в приложении или в шторке) убирается. На Android
  13+ без разрешения на уведомления ничего не ломается — список ожидающих работает.
- Кнопка «Остановить» в главной карточке статуса (видна, только когда сервер работает):
  шлёт команду `stop` и сразу обновляет карточку, не дожидаясь опроса. Если сервер уже
  не отвечает — понятное сообщение, а не ошибка. Факт ручной остановки запоминается,
  автозапуск не поднимет сервер до следующей перезагрузки.
- Автозапуск после перезагрузки (Android 11+, по умолчанию выключен): ожидание Wi-Fi,
  включение беспроводной отладки системной настройкой (нужно разрешение
  WRITE_SECURE_SETTINGS, которое Foxhole выдаёт себе через собственный сервер после
  явного подтверждения), подключение ранее спаренным ключом, запуск `start.sh`, по
  опции — выключение отладки обратно. Реализовано через WorkManager: ограниченный
  цикл попыток без зацикливания, итог — одно уведомление (успех или причина неудачи).
- Секция «Удаление приложений»: все установленные пакеты (пользовательские и системные)
  с поиском и фильтром «Пользовательские / Системные / Все», выбор галочками, «Выбрать
  всё», «Удалить выбранные». Открывается отдельным экраном с вкладками «Удаление» и
   «Восстановление» (переключатель сверху) — тапом по карточке на главном экране;
   закрытие — крестик или «Назад». Предупреждение
  о рисках показывается только при выборе
  системного пакета (при первой отметке за сессию и повторно в подтверждении, где
  кнопка «Удалить» становится активной через 3 секунды).
- Корзина «Удалённые» на 25 дней (вкладка «Восстановление»): APK пользовательских приложений (base + split через
  `pm path`) копируются перед удалением; восстановление через `pm install` /
  `pm install-multiple`; системные приложения скрываются (`pm uninstall -k --user 0`) и
  возвращаются через `pm install-existing --user 0`. «Восстановить», «Восстановить
  всё», «Удалить сейчас», «Очистить корзину», «Экспорт списка» в текстовый файл,
  суммарный размер корзины. Автоочистка при открытии приложения и ежедневно через
  WorkManager. Данные приложений не восстанавливаются — только сам APK.
- Галочка «Удалить безвозвратно» в подтверждении: пользовательские APK не сохраняются
  и в корзину не попадают (вернуть можно только заново скачав), для системных не
  создаётся записи (приложение физически остаётся скрытым в системе).

### Изменено
- Разрешения проверяются по уровню до обращения к серверу; отказ по уровню приходит
  клиенту понятным ответом и пишется в журнал.
- Включение автозапуска без спаренного ключа: вместо короткого сообщения — диалог
  с объяснением, что спаривание с ПК (`adb pair`) даёт ключ компьютеру, а не Foxhole,
  и кнопкой «Спарить сейчас» (переход к секции «Запуск без ПК»).
- Сообщение об ошибке запуска при отсутствии спаривания объясняет то же самое.
- Для полного списка пакетов в «Удалении приложений» добавлено разрешение
  QUERY_ALL_PACKAGES (приложение в Google Play не публикуется).
- POST_NOTIFICATIONS разово запрашивается при открытии приложения (Android 13+).
- Имя устройства ADB и CN сертификата приведены к «Foxhole» (было «RawBridge»).

### Исправлено
- При остановке сервера снекбар всегда упоминал автозапуск («только после
  перезагрузки»), даже если автозапуск не включался; теперь примечание показывается
  только при включённом автозапуске, иначе просто «Сервер остановлен».
- Снекбары и ошибки, показанные при открытой шторке «Настройки», оставались позади
  полупрозрачного фона BottomSheetDialog и были не видны — теперь они показываются
  в окне шторки поверх её содержимого.
- Недописанные секции «Удаление приложений» и «Удалённые» не существовали — реализованы.
- Замыкание слушателя автозапуска в настройках не компилировалось.
- Уведомление о запросе доступа не убиралось, если решение принималось в приложении.
- Остановка при уже мёртвом сервере показывала сырую ошибку вместо понятного сообщения.
- В манифесте было не заявлено разрешение WRITE_SECURE_SETTINGS — `pm grant` от сервера
  не срабатывал (система отвечала отказом), и автозапуск не включался. Статус разрешения
  в настройках теперь обновляется сразу после выдачи.
- Диалог уровня доступа применяет выбранную радио-кнопку — уровень сохраняется и при
  выдаче доступа, и по кнопке «Уровень» в списке разрешённых.
- Восстановление из корзины на прошивках без `pm install-multiple`: APK ставится
  командой `pm install -r --user 0` со всеми сохранёнными путями (base и split),
  файлы этапируются в `/data/local/tmp/foxhole_restore`.
- Если в поле порта спаривания ввести порт самого сервера Foxhole, показывается
  понятное сообщение («Это порт сервера Foxhole, а не порт спаривания»), а не
  неочевидный отказ.
- Галочки выбора приложений получили contentDescription («Выбрать <название>») —
  названия объявляются скринридером.
- Склонение счётчика приложений по правилам русского языка (1 приложение /
  2 приложения / 5 приложений).
- Ответ сервера на команду `stop` распознаётся корректно — ручная остановка не
  показывает ложную ошибку.
- Уведомление запроса доступа использует id по uid: одно уведомление на приложение,
  повторный запрос заменяет его вместо появления дублей.
- Ошибки спаривания показываются по-человечески: «Код или порт устарели — возьми
  свежие в настройках», «Порт спаривания закрыт: окно с кодом свернулось»,
  «ADB отклонил ключ…» вместо сырых исключений.
- Состояние открытой шторки сбрасывается при закрытии — повторное открытие и снекбары
  работают корректно.
- Кнопка «Открыть настройки отладки» надёжно открывает нужный экран: точные активности
  «Беспроводная отладка», где они есть, иначе сразу «Для разработчиков». Раньше рабочая
  ветка молча пропускалась (resolveActivity без <queries> на Android 11+ всегда давал
  null), а на Android 14+ прямой запуск фрагмента настройками игнорируется —
  открывался корень настроек.
- Автозапуск больше не срабатывает при перезапуске приложения: доставленный системе
  отложенный BOOT_COMPLETED заново будил воркер, и он мог поднять сервер вне
  перезагрузки. Теперь воркер выполняется не более одного раза на каждую загрузку
  и не трогает уже работающий сервер.

### Изменено
- Hero-карточка статуса упрощена: убраны чип «РАБОТАЕТ» и кнопка «Проверить» — статус
  виден по точке и заголовку и обновляется автоматически каждые 5 с.
- Оба варианта запуска («Запуск с ПК» и «Запуск без ПК») всегда развёрнуты и не
  сворачиваются; «Запуск с ПК» стоит первым.
- «Запуск с ПК» упрощён до одной кнопки «Посмотреть команду»: Foxhole записывает
  файл и открывает диалог с командой и кнопками «Переслать» и «Скопировать».
- Секции «Журнал приложений», «Как это работает» и «Гайды» сворачиваются тапом
  по заголовку с анимацией (скольжение + затухание, bounce заголовка), стрелка ▾/▸
  показывает состояние; выбор запоминается и восстанавливается после перезапуска.
  Секции запуска «Запуск с ПК» и «Запуск без ПК» остаются всегда развёрнутыми.
  Панели «Приложения» и «Удаление приложений» открываются со скольжением снизу.
- После спаривания идут «Команды», затем карточка «Приложения» (шеврон, отдельное окно
  с вкладками «Доступ» и «Установленные»), затем «Удаление приложений», «Журнал
  приложений», «Как это работает» и «Гайды». Кнопка «Показать команду для ADB»
  переехала в «Гайды».
- Карточка «Удаление приложений» открывается только тапом по карточке: кнопка «Открыть»
  убрана, справа — шеврон «❯».

### Проверено
- Автозапуск после перезагрузки проверен целиком на реальном устройстве (PixelOS,
  Android 17): включён переключатель, телефон перезагружен —
  приёмник загрузки не упал, Foxhole сам включил беспроводную отладку
  (WRITE_SECURE_SETTINGS), подключился спаренным ключом, запустил сервер и показал
  одно уведомление «Запущен после перезагрузки»; сервер слушает порт и отвечает.

### Не проверено
- Поведение автозапуска на широком наборе прошивок (MIUI, HyperOS, One UI и другие)
  и ограничения фонового запуска. Удаление, скрытие и восстановление пакетов проверены
  на Android 17.

## [1.1] — 2026-10-20

### Добавлено
- Экран настроек (шестерёнка в шапке):
  - порт локального сервера (по умолчанию 27183);
  - автопроверка статуса сервера при открытии;
  - подтверждение перед выдачей доступа приложению;
  - сброс токена и удаление ADB-ключа.
- Подтверждение выдачи доступа через диалог с uid и списком возможностей.
- Экран настроек показывает версию приложения и версию Android.
- Произвольные shell-команды от uid 2000: `dumpsys`, `ps`, `ls`, конвейеры — всё, что умеет `sh -c`.
- Собственные шрифты интерфейса: Inter и JetBrains Mono (не зависят от системного).
- Поддержка Android 8+ (API 26): на версиях младше 11 секция Wi-Fi-спаривания отключается с пояснением, сервер запускается с ПК.
- Список установленных приложений с поиском: доступ можно выдать заранее, не дожидаясь запроса.
- Гайды в приложении: беспроводная отладка и запуск shell с ПК.
- Кнопка «Показать команду для ADB» — готовые `adb pair` и `adb connect`.
- Кнопка «Создать файл запуска» в секции «Запуск с ПК»: записывает `start.sh` во внешнее хранилище приложения, показывает готовую команду `adb shell sh "<путь>"` и копирует её в буфер обмена.
- Автопроверка сервера каждые 5 секунд, пока приложение открыто.
- [store-listing.md](store-assets/store-listing.md) — краткое и полное описание для магазина.

### Изменено
- Автопроверка статуса — не только при открытии, а каждые 5 секунд (отключается в настройках).
- Спаривание по Wi-Fi без разделённого экрана: порт и код вводятся в уведомлении Foxhole, системные настройки можно не закрывать.
- После успешного спаривания сервер запускается автоматически и проверяется через `ping`.
- Ошибки и успехи показываются Snackbar-уведомлениями.
- Новый дизайн: hero-карточка с живым индикатором статуса, сворачиваемые карточки, аватары приложений, аккуратная консоль вывода.
- Собственная палитра для светлой и тёмной темы; на Android 12+ — Material You (цвета обоев).
- Настройки вынесены в нижний лист (bottom sheet) с шестерёнкой в шапке.
- Минимальная версия — Android 8 (API 26); Wi-Fi-спаривание по-прежнему требует Android 11+.
- Порт сервера передаётся в `start.sh` и учитывается клиентом.
- Резервное копирование и перенос данных исключены правилами `data_extraction_rules`.

### Исправлено
- `start.sh` переживает обновление приложения (путь к APK берётся через `pm path`).
- Подпись release-сборки из секретов GitHub Actions.
- Устранён краш при повреждённых ADB-ключах в SharedPreferences.
- Ограничено число потоков сервера (защита от исчерпания ресурсов).
- Таймаут shell-команд (20 с) и скрытие внутренних ошибок от клиентов.
- Вывод ограничен 128 КиБ: большие ответы (`dumpsys`) обрезаются, а не вешают сервер.
- Многострочные команды отклоняются вместо молчаливого обрезания.
- Гонка при генерации токена.
- `putsetting` принимает значения с пробелами и минусом.

### Добавлено

  журнал запросов, запуск через беспроводную отладку и через `start.sh` с ПК.
