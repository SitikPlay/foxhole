Shell-доступ без root, который ты контролируешьShell access without root, under your control

Foxhole запускает маленький сервер с правами shell и даёт выбранным приложениям выполнять shell-команды. Каждое приложение ты разрешаешь вручную и можешь отозвать в один тап.Foxhole starts a small server with shell privileges and lets selected apps run shell commands. You approve each app by hand and can revoke access with one tap.

Версия 1.1.0. Работает на Android 8 и выше; спаривание по Wi-Fi — только с Android 11. Проверено не на всех прошивках.Version 1.1.0. Works on Android 8 and up; Wi-Fi pairing only on Android 11+. Not tested on every firmware.

Установка и запускInstall and launch

Без компьютераWithout a computer

Android 11 и вышеAndroid 11 and up

  1. Установи и открой FoxholeInstall and open Foxhole

    Скачай APK со страницы релизов, установи и открой приложение.Download the APK from the releases page, install it and open the app.

  2. Включи беспроводную отладкуTurn on wireless debugging

    Настройки → Для разработчиков → Беспроводная отладка. Нужен Wi-Fi. Если раздела нет, семь раз нажми на «Номер сборки» в «О телефоне».Settings → Developer options → Wireless debugging. You need Wi-Fi. If there is no such section, tap Build number seven times in About phone.

  3. Открой окно с кодомOpen the pairing window

    Нажми «Подключение устройства по коду». Появятся шестизначный код и порт.Tap Pair device with pairing code. A six-digit code and a port appear.

  4. Введи порт и код в уведомленииEnter the port and code in the notification

    Потяни шторку, впиши порт и код в уведомлении Foxhole и нажми «Спарить». Сервер запустится сам. Окно с кодом закрывать не нужно.Pull down the shade, type the port and code into the Foxhole notification and tap Pair. The server starts by itself. Keep the pairing window open.

  5. ГотовоDone

    Теперь можно разрешать приложения.Now you can approve apps.

С компьютеромWith a computer

Android 8 и вышеAndroid 8 and up

  1. Подключи телефон кабелемConnect the phone with a cable

    Соедини телефон с компьютером USB-кабелем.Plug the phone into the computer with a USB cable.

  2. Включи отладку по USBTurn on USB debugging

    Включи режим разработчика (семь нажатий на «Номер сборки»), затем «Отладка по USB» в разделе «Для разработчиков». На Xiaomi, Redmi и POCO включи ещё «Отладка по USB (настройки безопасности)». В окне на телефоне разреши отладку для этого компьютера.Enable developer mode (tap Build number seven times), then turn on USB debugging in Developer options. On Xiaomi, Redmi and POCO also turn on USB debugging (Security settings). Allow debugging for this computer in the dialog on the phone.

  3. Скопируй команду из FoxholeCopy the command from Foxhole

    Команду для запуска можно получить в приложении: выбери запуск через компьютер и скопируй её. Она зависит от телефона, поэтому бери её именно из приложения.You can get the launch command in the app: choose launch through a computer and copy it. It depends on the phone, so take it from the app itself.

  4. Выполни её в ADBRun it in ADB

    Скачай platform-tools, открой терминал в их папке, вставь команду и нажми Enter. В Windows PowerShell перед командой добавь .\, то есть .\adb shell ….Download platform-tools, open a terminal in its folder, paste the command and press Enter. In Windows PowerShell put .\ before the command, like .\adb shell ….

  5. ГотовоDone

    Сервер запущен, теперь можно разрешать приложения.The server is running, now you can approve apps.

После перезагрузки телефона сервер нужно запустить заново.After the phone restarts, start the server again.

Что разрешеноWhat is allowed

Любая shell-командаAny shell command
dumpsys, ps, ls, конвейеры и всё остальное — через sh -c от uid 2000.dumpsys, ps, ls, pipelines and anything else — via sh -c as uid 2000.
ping
Проверить, что сервер работает.Check that the server is running.
grant <пакет> <permission>grant <package> <permission>
Выдать приложению runtime-разрешение.Grant an app a runtime permission.
revoke <пакет> <permission>revoke <package> <permission>
Забрать разрешение.Take a permission back.
appop <пакет> <OP> <режим>appop <package> <OP> <mode>
Изменить appops: allow, ignore, deny, default или foreground.Change an app op: allow, ignore, deny, default or foreground.
getsetting <область> <ключ>getsetting <namespace> <key>
Прочитать системную настройку из global, secure или system.Read a system setting from global, secure or system.
putsetting <область> <ключ> <значение>putsetting <namespace> <key> <value>
Записать системную настройку.Write a system setting.
Уровни доступаAccess levels
READ — только чтение (ping, getsetting). PERMISSIONS — плюс grant, revoke, appop, putsetting. FULL — любые команды. Уровень выбирается при выдаче доступа и меняется позже без отзыва.READ — read-only (ping, getsetting). PERMISSIONS — plus grant, revoke, appop, putsetting. FULL — any commands. You pick a level when granting access and can change it later without revoking.

Алиасы узнаются по первому слову; всё нераспознанное и команды с конвейерами и подстановками считаются FULL — обходы вида getsetting global x; rm -rf / на уровне READ не проходят. Также внутри менеджера есть удаление приложений: пользовательские приложения перед удалением копируются в корзину «Удалённые» на 25 дней, откуда их можно восстановить (данные приложения не восстанавливаются); системные не удаляются физически — только скрываются для тебя и возвращаются в любой момент. Это возможно только из самого менеджера: через провайдер такие команды доступны лишь на уровне FULL.Aliases are matched by the first word; anything unrecognized, plus pipelines and substitutions, counts as FULL — bypasses like getsetting global x; rm -rf / do not pass at READ level. Housekeeping: the manager can also uninstall apps. User apps are backed up to a 25-day "Deleted" trash before removal and can be restored from it (app data is not restored); system apps aren't physically removed — they're only hidden for you and can be brought back any time. This works only from the manager itself: through the provider such commands require the FULL level.

Вывод ограничен 128 КиБ, таймаут команды — 20 секунд. Останавливать сервер может только сам менеджер.Output is capped at 128 KiB and commands time out after 20 seconds. Only the manager itself can stop the server.

БезопасностьSecurity

  • Сервер слушает только localhost и принимает запросы по секретному токену.The server listens on localhost only and accepts requests with a secret token.
  • Доступ привязан к uid приложения, а не к его названию, поэтому подделать его нельзя.Access is tied to the app’s uid, not its name, so it cannot be spoofed.
  • Каждый запрос попадает в журнал, который можно открыть в приложении.Every request is written to a log you can open in the app.
  • Без рекламы и сбора данных. Исходный код открыт под GPL-3.0.No ads and no data collection. The source code is open under GPL-3.0.

Права shell широкие, поэтому разрешай только те приложения, которым доверяешь.Shell privileges are broad, so only allow apps you trust.

Для разработчиковFor developers

Твоё приложение вызывает провайдер Foxhole. При первом вызове оно получит отказ и появится в списке ожидающих, а после разрешения вызовы заработают. Вызывать нужно не из главного потока.Your app calls the Foxhole provider. The first call is rejected and the app appears in the pending list; after you allow it, calls go through. Do not call it from the main thread.

val uri = Uri.parse("content://com.sitikplay.foxhole.bridge")
val r = contentResolver.call(uri, "exec", "ping", null)
val ok = r?.getBoolean("ok") == true
val text = r?.getString("result")
