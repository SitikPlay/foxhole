# Foxhole

[![Build](https://github.com/SitikPlay/foxhole/actions/workflows/build.yml/badge.svg)](https://github.com/SitikPlay/foxhole/actions/workflows/build.yml)
[![Latest release](https://img.shields.io/github/v/release/SitikPlay/foxhole?include_prereleases)](https://github.com/SitikPlay/foxhole/releases)
[![License: GPL-3.0](https://img.shields.io/badge/license-GPL--3.0--or--later-blue)](LICENSE)
[![minSdk](https://img.shields.io/badge/Android-8%2B%20(API%2026)-green)](https://developer.android.com/about/versions/oreo)

Открытый менеджер shell-доступа для Android без root. Foxhole запускает небольшой серверный процесс с правами `shell` (uid 2000) и даёт приложениям, которым ты доверяешь, выполнять команды от имени shell.



*English: Foxhole is an open-source, root-free shell-access broker for Android. It runs a small server process as the `shell` user and lets apps you approve run shell commands as that user. Prototype, GPL-3.0.*

## Требования

| Что | Требование |
| --- | --- |
| Android | **8 (API 26) или новее** |
| Запуск с ПК | любая поддерживаемая версия Android |
| Спаривание по Wi-Fi | **только Android 11+** — функция `adb pair` появилась в Android 11 |
| Root | **не нужен** |

На Android младше 11 беспроводная отладка с TLS-спариванием (`_adb-tls-pairing._tcp`) недоступна: Foxhole показывает это в секции «Запуск без ПК» и отключает поля. Сервер на таких версиях запускается с ПК через `start.sh`.

## Как это работает

1. Приложение-менеджер запускает сервер через `app_process` с правами shell. Запуск идёт либо через беспроводную отладку прямо с телефона, либо командой `adb shell` с ПК.
2. Сервер слушает только `127.0.0.1` и принимает запросы только с секретным токеном.
3. Сторонние приложения общаются с Foxhole через `ContentProvider`. Незнакомое приложение получает отказ и появляется в списке ожидающих. Ты решаешь в Foxhole, разрешить его или нет. В окне «Приложения» есть вкладка «Установленные» с поиском: доступ можно выдать заранее.
4. Все запросы записываются в журнал (последние 200).
5. Пока приложение открыто, статус сервера проверяется каждые 5 секунд.

Это классическая схема запуска Java-процесса через `app_process` от uid 2000, но без Binder: Foxhole общается с сервером по localhost и выполняет команды через `sh -c`.

## Что разрешено

Каждому приложению выдаётся **уровень доступа** (проверяется до отправки на сервер):

| Уровень | Что умеет приложение |
| --- | --- |
| **READ** | `ping`, `getsetting` — безобидное чтение (по умолчанию для новых доступов) |
| **PERMISSIONS** | READ плюс `grant`, `revoke`, `appop`, `putsetting` |
| **FULL** | любые shell-команды, как раньше |

Алиасы узнаются по первому слову; всё нераспознанное, а также команды с разделителями,
подстановками и конвейерами считаются FULL — обходы вида `getsetting global x; rm -rf /`
на уровне READ не проходят. Отказ по уровню пишется в журнал. Уровень выбирается в
диалоге выдачи доступа и меняется позже без отзыва (кнопка «Уровень» в списке
разрешённых). Доступы, выданные до 1.2.0, остаются FULL.

Сервер выполняет **любые shell-команды** от uid 2000: `dumpsys`, `ps`, `ls`, `pm`, `settings`, конвейеры (`cmd | head`) и т.д. Вывод возвращается клиенту, ограничен 128 КиБ, таймаут — 20 секунд. Команда должна быть одной строкой.

Для частых операций есть короткие алиасы с проверкой аргументов:

| Команда | Что делает |
| --- | --- |
| `ping` | проверка сервера |
| `grant <пакет> <permission>` | выдать runtime-разрешение (`pm grant`) |
| `revoke <пакет> <permission>` | отозвать разрешение (`pm revoke`) |
| `appop <пакет> <OP> <allow\|ignore\|deny\|default\|foreground>` | изменить appops |
| `getsetting <global\|secure\|system> <ключ>` | прочитать системную настройку |
| `putsetting <global\|secure\|system> <ключ> <значение>` | записать системную настройку |

Всё остальное исполняется как есть через `sh -c`. Останавливать сервер может только сам менеджер — сторонним приложениям команда `stop` запрещена. Кнопка «Остановить» в главной карточке завершает сервер и сразу обновляет статус; вручную остановленный сервер автозапуск не поднимет до следующей перезагрузки.

## Установка и запуск

1. Скачай APK из [Releases](../../releases) и установи.
2. Включи «Беспроводная отладка» (Настройки → Для разработчиков), телефон должен быть в Wi-Fi.
3. В Foxhole открой **«Запуск без ПК»** и нажми **«Открыть настройки отладки»**. Разреши уведомления, если система спросит.
4. На экране настроек нажми «Подключение устройства по коду» — появятся порт и код. Не закрывая настройки, открой шторку уведомлений, разверни уведомление Foxhole, нажми **«Ввести порт и код»** и введи `порт код` (через пробел).
5. Foxhole спарит устройство и предложит открыть приложение. Сервер запустится сам; статус в верхней карточке станет «Сервер работает» — точка зелёная и пульсирует. Пока приложение открыто, статус обновляется автоматически каждые 5 секунд (настройка «Автопроверка сервера»).

Секции «Журнал приложений», «Как это работает» и «Гайды» сворачиваются тапом по заголовку — состояние запоминается. «Запуск с ПК» и «Запуск без ПК» всегда развёрнуты.

Когда стороннее приложение впервые обратится к провайдеру, оно попадёт в список ожидающих и появится в уведомлении Foxhole с кнопками «Разрешить (READ)» и «Отклонить» — или реши в самом приложении в окне «Приложения» (тап по карточке со стрелочкой; вкладки «Доступ» и «Установленные»). Не обязательно ждать: доступ можно выдать заранее на вкладке «Установленные».

Кнопка «Показать команду для ADB» в секции «Гайды» выдаст готовые `adb pair` и `adb connect` для спаривания с компьютером. Спаривание с ПК не заменяет «Запуск без ПК»: оно даёт ключ компьютеру, а не Foxhole — для автозапуска нужен ключ самого приложения, поэтому спарь по Wi-Fi один раз.

На Android 8–10 беспроводное спаривание недоступно — используй «Запуск с ПК» (шаги ниже).

Код спаривания действует около 2 минут. Если спаривание не удалось — Foxhole покажет причину во всплывающем уведомлении.

После перезагрузки телефона сервер нужно запускать заново — это ограничение метода без root. Обойти его можно переключателем **«Автозапуск после перезагрузки»** (Android 11+, см. «Настройки»): Foxhole сам включит беспроводную отладку, подключится спаренным ключом и запустит сервер.

## Настройки

Открываются шестерёнкой в шапке:

- **Порт сервера** — localhost-порт (по умолчанию `27183`). Применяется после перезапуска сервера и попадает в `start.sh`.
- **Автопроверка сервера** — `ping` каждые 5 секунд, пока приложение открыто.
- **Подтверждать выдачу доступа** — диалог с uid, уровнем доступа и списком возможностей перед разрешением приложению.
- **Автозапуск после перезагрузки** (Android 11+, по умолчанию выключен) — честные условия: нужно разрешение WRITE_SECURE_SETTINGS (Foxhole выдаёт его себе через собственный сервер после явного подтверждения), Wi-Fi и спаренный ключ из «Запуск без ПК»; на некоторых прошивках фоновый старт может не сработать. Выключение переключателя отменяет автозапуск. После ручной остановки сервера автозапуск сработает только на следующей перезагрузке.
- **Выключать отладку после автозапуска** (включено по умолчанию) — отладка выключается, только если её включал сам автозапуск.
- **Сбросить токен** — новый секрет для связи с сервером (сервер нужно перезапустить).
- **Забыть ADB-ключ** — удаляет ключ и сертификат; после этого нужно спариваться заново.

Интерфейс использует собственные шрифты (Inter и JetBrains Mono) и не зависит от системного. В секции «Гайды» — пошаговые инструкции для беспроводной отладки и запуска с ПК.

## Удаление приложений

Секция на главном экране открывает **отдельный экран с вкладками «Удаление» и
«Восстановление»** (переключаются сверху; закрытие — крестик или «Назад») — тапом
по самой карточке (справа — шеврон «❯»). Нужен
работающий сервер. Список всех установленных пакетов — пользовательских и системных — с
поиском и фильтром «Пользовательские / Системные / Все», выбор галочками и «Выбрать всё».
Защитного списка запрещённых пакетов нет: можно выбрать любой.

- **Пользовательские** удаляются через `pm uninstall`. Перед удалением APK (base и все
  split через `pm path`) копируется в корзину «Удалённые».
- **Системные** не удаляются физически: `pm uninstall -k --user 0` скрывает приложение
  только для тебя. Приложение остаётся в системном разделе, место не освобождается,
  данные остаются.
- Предупреждение о рисках («удаление некоторых системных пакетов может сломать
  телефон или помешать его загрузке») показывается **только при выборе системного
  пакета**: при первой отметке за сессию и повторно в подтверждении, где кнопка
  «Удалить» активируется через 3 секунды. Для пользовательских — короткое нейтральное
  «Удалить N приложений?».
- Каждый пакет обрабатывается отдельно: ошибка одного не прерывает остальные, вывод
  прошивок (включая `DELETE_FAILED_DEVICE_POLICY_MANAGER`) показывается как есть.
- Если скопировать APK не удалось, Foxhole честно предупредит, что восстановление
  будет невозможно, и спросит, продолжать ли.
- **«Удалить безвозвратно»** (по умолчанию выключена): пользовательские APK не
  сохраняются и в корзину не попадают (вернуть можно только заново скачав приложение);
  для системных не создаётся записи, но приложение физически остаётся скрытым.

## Корзина «Удалённые»

Вкладка «Восстановление» отдельного экрана: хранит удалённые через Foxhole приложения
25 дней, затем чистит автоматически (при открытии приложения и ежедневно в фоне).
После этого срока кнопка «Восстановить» пропадает; скрытое системное приложение можно
вернуть только командой `pm install-existing --user 0 <пакет>`.

- «Восстановить» ставит приложение из сохранённых APK одной командой
  `pm install -r --user 0` со всеми путями (base и split; работает и на прошивках без
  `pm install-multiple`); системные возвращаются через `pm install-existing --user 0`.
  **Данные приложения не восстанавливаются** — только сам APK.
- «Восстановить всё», «Удалить сейчас», «Очистить корзину», «Экспорт списка» (текстовый
  файл в папке приложения) и суммарный размер корзины — в той же секции.

## Запуск с ПК

Вместо шагов 2–5: в секции «Запуск с ПК» нажми **«Посмотреть команду»** — Foxhole запишет `start.sh` и сразу покажет диалог с командой и кнопками **«Переслать»** (Share → любой терминал/мессенджер на ПК) и **«Скопировать»**. Вставь команду в терминал и выполни:

```bash
adb shell sh "/storage/emulated/0/Android/data/com.sitikplay.foxhole/files/start.sh"
```

Скрипт сам находит путь к APK через `pm path`, поэтому переживает обновление приложения.

## Для разработчиков: как подключить своё приложение

В манифесте клиентского приложения (Android 11+ требует видимость провайдера):

```xml
<queries>
    <provider android:authorities="com.sitikplay.foxhole.bridge" />
</queries>
```

Вызов:

```kotlin
val uri = Uri.parse("content://com.sitikplay.foxhole.bridge")
val r = contentResolver.call(uri, "exec", "grant com.example.app android.permission.WRITE_SECURE_SETTINGS", null)
val ok = r?.getBoolean("ok") == true
val text = r?.getString("result")
```

При первом вызове придёт отказ, и приложение появится в списке ожидающих в Foxhole. Пользователь разрешает его, после этого вызовы работают. По умолчанию выдаётся уровень READ (только `ping` и `getsetting`) — для `grant`/`putsetting` пользователь может поднять уровень до PERMISSIONS в диалоге выдачи или позже кнопкой «Уровень». Вызывать нужно не из главного потока.

## Безопасность

- Доступ выдаётся по **uid** вызывающего приложения. Имя пакета только для показа, подделать uid нельзя.
- **Уровни доступа** — принцип наименьших привилегий: большинству приложений хватает READ, PERMISSIONS нужен только для управления разрешениями, FULL — для особых случаев. Проверка выполняется до отправки на сервер, обходы конвейерами и подстановками считаются FULL.
- Сервер слушает только localhost и требует токен, который хранится в приватном хранилище приложения.
- Название приложения для уведомлений берётся из PackageManager по uid — данные, присланные клиентом, для показа не используются.
- Список ожидающих ограничен (20), чтобы его нельзя было засорить.
- Резервное копирование отключено: ключи и токены не попадают в облако.
- Права shell очень широкие: теперь разрешены любые команды, включая `dumpsys`. Разрешай только приложения, которым доверяешь, и отзывай доступ, когда он не нужен. Для осторожных приложений выдавай READ или PERMISSIONS вместо FULL.
- Огромный вывод обрезается (128 КиБ), команды с бесконечным выводом завершаются по таймауту (20 с).
- Разрешение WRITE_SECURE_SETTINGS для автозапуска выдаётся только после явного подтверждения; отозвать можно с ПК: `adb shell pm revoke com.sitikplay.foxhole android.permission.WRITE_SECURE_SETTINGS`.
- Ключ ADB хранится в приватном хранилище приложения без дополнительного шифрования (план: Android Keystore). Компрометация самого приложения-менеджера означает компрометацию всего механизма: оно выдаёт доступ, держит токен и ADB-ключ.
- Библиотека [libadb-android](https://github.com/MuntashirAkon/libadb-android) не проходила аудит безопасности. ADB используется только для запуска сервера, после этого соединение закрывается.

Нашёл уязвимость? Не открывай публичный issue — см. [SECURITY.md](SECURITY.md).

## Чего нет (пока)

- Восстановления **данных** приложений из корзины — только сам APK (и это принципиально: удалить данные, не удаляя приложение, нельзя).
- Реального удаления системных пакетов — только скрытие для пользователя 0 (без root это и есть максимум).
- Проверки на широком наборе устройств: MIUI/HyperOS, One UI и другие прошивки не тестировались — особенно автозапуск после перезагрузки и удаление/восстановление пакетов.
- Дополнительного шифрования ADB-ключа (план: Android Keystore).

## Сборка из исходников

Нужны Android Studio (или JDK 17) и интернет для Gradle.

```bash
git clone https://github.com/SitikPlay/foxhole
cd Foxhole
./gradlew assembleDebug      # app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease    # app/build/outputs/apk/release/
```

Полный E2E на подключённом разблокированном телефоне:

```powershell
.\tools\e2e-pair.cmd
```

Скрипт собирает и ставит debug APK, выдаёт разрешение на уведомления, включает беспроводную отладку, спаривает устройство и проверяет сервер. Флаг `-SkipBuild` пропускает сборку, `-NoPcPair` не проверяет `adb pair` с компьютера.

Минификация и оптимизация R8 в релизе **выключены**: серверный класс запускается через `app_process` по имени (`com.sitikplay.foxhole.Server`), обфускация сломала бы запуск. Защита на случай включения R8 лежит в `app/src/main/keepRules/rules.keep`.

### Релизы и подпись

[Workflow](.github/workflows/build.yml) собирает debug и release APK на каждый push/PR, а по тегу `v*` публикует GitHub Release.

Для подписи релиза добавь в **Settings → Secrets and variables → Actions**:

| Секрет | Значение |
| --- | --- |
| `KEYSTORE_B64` | keystore в base64: `base64 -w0 release.jks` |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | alias ключа |
| `KEY_PASSWORD` | пароль ключа |

Если секреты не заданы, release APK собирается неподписанным, и в релиз автоматически попадает debug-подписанный APK (с суффиксом `-debug`). Его можно установить, но обновить поверх подписанного релиза нельзя.
