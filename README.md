# Foxhole

[![Build](https://github.com/SitikPlay/foxhole/actions/workflows/build.yml/badge.svg)](https://github.com/SitikPlay/foxhole/actions/workflows/build.yml)
[![Latest release](https://img.shields.io/github/v/release/SitikPlay/foxhole?include_prereleases)](https://github.com/SitikPlay/foxhole/releases)
[![License: GPL-3.0](https://img.shields.io/badge/license-GPL--3.0--or--later-blue)](LICENSE)
[![minSdk](https://img.shields.io/badge/Android-8%2B%20(API%2026)-green)](https://developer.android.com/about/versions/oreo)

Открытый менеджер shell-доступа для Android без root. Foxhole запускает небольшой серверный процесс с правами `shell` (uid 2000) и даёт приложениям, которым ты доверяешь, выполнять команды от имени shell.

> Версия 1.1.0. Возможны баги на отдельных прошивках.

*English: Foxhole is an open-source, root-free shell-access broker for Android. It runs a small server process as the `shell` user and lets apps you approve run shell commands as that user. Version 1.1.0, GPL-3.0.*

## Требования

| Что | Требование |
| --- | --- |
| Android | **8 (API 26) или новее** |
| Запуск с ПК | любая поддерживаемая версия Android |
| Спаривание по Wi-Fi | **только Android 11+** — функция `adb pair` появилась в Android 11 |
| Root | **не нужен** |

На Android младше 11 беспроводная отладка с TLS-спариванием (`_adb-tls-pairing._tcp`) недоступна: Foxhole показывает это в секции «Запуск без ПК» и отключает поля. Сервер на таких версиях запускается с ПК через `start.sh`.

## Как это работает

1. Приложение-менеджер запускает сервер через `app_process` с правами shell. Запуск идёт либо через беспроводную отладку прямо с телефона, либо командой `adb shell` с ПК.
2. Сервер слушает только `127.0.0.1` и принимает запросы только с секретным токеном.
3. Сторонние приложения общаются с Foxhole через `ContentProvider`. Незнакомое приложение получает отказ и появляется в списке ожидающих. Ты решаешь в Foxhole, разрешить его или нет. В отдельной секции «Установленные приложения» есть поиск: доступ можно выдать заранее.
4. Все запросы записываются в журнал (последние 200).
5. Пока приложение открыто, статус сервера проверяется каждые 5 секунд.

Это классическая схема запуска Java-процесса через `app_process` от uid 2000, но без Binder: Foxhole общается с сервером по localhost и выполняет команды через `sh -c`.

## Что разрешено

Сервер выполняет **любые shell-команды** от uid 2000: `dumpsys`, `ps`, `ls`, `pm`, `settings`, конвейеры (`cmd | head`) и т.д. Вывод возвращается клиенту, ограничен 128 КиБ, таймаут — 20 секунд. Команда должна быть одной строкой.

Для частых операций есть короткие алиасы с проверкой аргументов:

| Команда | Что делает |
| --- | --- |
| `ping` | проверка сервера |
| `grant <пакет> <permission>` | выдать runtime-разрешение (`pm grant`) |
| `revoke <пакет> <permission>` | отозвать разрешение (`pm revoke`) |
| `appop <пакет> <OP> <allow\|ignore\|deny\|default\|foreground>` | изменить appops |
| `getsetting <global\|secure\|system> <ключ>` | прочитать системную настройку |
| `putsetting <global\|secure\|system> <ключ> <значение>` | записать системную настройку |

Всё остальное исполняется как есть через `sh -c`. Останавливать сервер может только сам менеджер — сторонним приложениям команда `stop` запрещена.

## Установка и запуск

Скачай APK из [Releases](../../releases) и установи. Дальше выбери способ запуска.

### Без компьютера (Android 11+)

1. Включи режим разработчика: в «О телефоне» семь раз нажми на «Номер сборки».
2. Включи «Беспроводная отладка» (Настройки → Для разработчиков). Телефон должен быть в Wi-Fi.
3. В Foxhole открой **«Запуск без ПК»** и нажми **«Открыть настройки отладки»**. Разреши уведомления, если система спросит.
4. На экране настроек нажми «Подключение устройства по коду» — появятся порт и код. Не закрывая настройки, открой шторку уведомлений, разверни уведомление Foxhole, нажми **«Ввести порт и код»** и введи `порт код` (через пробел).
5. Foxhole спарит устройство и предложит открыть приложение. Сервер запустится сам; статус в верхней карточке станет «Сервер работает». Кнопка «Проверить» шлёт `ping` и показывает ответ `OK pong uid=2000`.

Код спаривания действует около 2 минут. Если спаривание не удалось — Foxhole покажет причину во всплывающем уведомлении.

### С компьютером (Android 8+)

Подходит для Android 8–10, где беспроводное спаривание недоступно, и для тех, кому проще с компьютером.

1. Подключи телефон к компьютеру USB-кабелем.
2. Включи режим разработчика (семь нажатий на «Номер сборки») и «Отладка по USB» в разделе «Для разработчиков». На Xiaomi, Redmi и POCO включи ещё «Отладка по USB (настройки безопасности)». В окне на телефоне разреши отладку для этого компьютера.
3. В Foxhole открой **«Запуск с ПК»** и нажми **«Создать файл запуска»**: приложение запишет `start.sh` и сразу скопирует команду. Её же можно взять из поля «Команда для ПК» (есть кнопка «Скопировать команду»).
4. Скачай [platform-tools](https://developer.android.com/tools/releases/platform-tools), открой терминал в их папке, вставь команду и нажми Enter. В Windows PowerShell перед командой добавь `.\`, то есть `.\adb shell …`.

Команда выглядит примерно так, но путь на твоём телефоне может отличаться, поэтому бери её из приложения:

```bash
adb shell sh "/storage/emulated/0/Android/data/com.sitikplay.foxhole/files/start.sh"
```

Скрипт сам находит путь к APK через `pm path`, поэтому переживает обновление приложения. Кнопка «Показать команду для ADB» в этой же секции выдаёт готовые `adb pair` и `adb connect`, если хочешь спариться с компьютером по Wi-Fi.

После перезагрузки телефона сервер нужно запускать заново. Это ограничение метода без root.

## Настройки

Открываются шестерёнкой в шапке:

- **Порт сервера** — localhost-порт (по умолчанию `27183`). Применяется после перезапуска сервера и попадает в `start.sh`.
- **Автопроверка сервера** — `ping` каждые 5 секунд, пока приложение открыто.
- **Подтверждать выдачу доступа** — диалог с uid и списком возможностей перед разрешением приложению.
- **Сбросить токен** — новый секрет для связи с сервером (сервер нужно перезапустить).
- **Забыть ADB-ключ** — удаляет ключ и сертификат; после этого нужно спариваться заново.

Интерфейс использует собственные шрифты (Inter и JetBrains Mono) и не зависит от системного. В секции «Гайды» — пошаговые инструкции для беспроводной отладки и запуска с ПК.

## Для разработчиков: как подключить своё приложение

В манифесте клиентского приложения (Android 11+ требует видимость провайдера):

```xml
<queries>
    <provider android:authorities="com.sitikplay.foxhole.bridge" />
</queries>
```

Вызов:

```kotlin
val uri = Uri.parse("content://com.sitikplay.foxhole.bridge")
val r = contentResolver.call(uri, "exec", "grant com.example.app android.permission.WRITE_SECURE_SETTINGS", null)
val ok = r?.getBoolean("ok") == true
val text = r?.getString("result")
```

При первом вызове придёт отказ, и приложение появится в списке ожидающих в Foxhole. Пользователь разрешает его, после этого вызовы работают. Вызывать нужно не из главного потока.

## Безопасность

- Доступ выдаётся по **uid** вызывающего приложения. Имя пакета только для показа, подделать uid нельзя.
- Сервер слушает только localhost и требует токен, который хранится в приватном хранилище приложения.
- Список ожидающих ограничен (20), чтобы его нельзя было засорить.
- Резервное копирование отключено: ключи и токены не попадают в облако.
- Права shell очень широкие: теперь разрешены любые команды, включая `dumpsys`. Разрешай только приложения, которым доверяешь, и отзывай доступ, когда он не нужен.
- Огромный вывод обрезается (128 КиБ), команды с бесконечным выводом завершаются по таймауту (20 с).
- Ключ ADB хранится в приватном хранилище приложения без дополнительного шифрования (план: Android Keystore).
- Библиотека [libadb-android](https://github.com/MuntashirAkon/libadb-android) не проходила аудит безопасности. ADB используется только для запуска сервера, после этого соединение закрывается.

Нашёл уязвимость? Не открывай публичный issue — см. [SECURITY.md](SECURITY.md).

## Чего нет (пока)

- Автозапуска после перезагрузки.
- Уведомления о новом запросе (список обновляется при открытии приложения).
- Детальных прав по операциям для каждого приложения.
- Проверки на широком наборе устройств.

## Сборка из исходников

Нужны Android Studio (или JDK 17) и интернет для Gradle.

```bash
git clone https://github.com/SitikPlay/foxhole
cd foxhole
./gradlew assembleDebug      # app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease    # app/build/outputs/apk/release/
```

Полный E2E на подключённом разблокированном телефоне:

```powershell
.\tools\e2e-pair.cmd
```

Скрипт собирает и ставит debug APK, выдаёт разрешение на уведомления, включает беспроводную отладку, спаривает устройство и проверяет сервер. Флаг `-SkipBuild` пропускает сборку, `-NoPcPair` не проверяет `adb pair` с компьютера.

Минификация и оптимизация R8 в релизе **выключены**: серверный класс запускается через `app_process` по имени (`com.sitikplay.foxhole.Server`), обфускация сломала бы запуск. Защита на случай включения R8 лежит в `app/src/main/keepRules/rules.keep`.

### Релизы и подпись

[Workflow](.github/workflows/build.yml) собирает debug и release APK на каждый push/PR, а по тегу `v*` публикует GitHub Release.

Для подписи релиза добавь в **Settings → Secrets and variables → Actions**:

| Секрет | Значение |
| --- | --- |
| `KEYSTORE_B64` | keystore в base64: `base64 -w0 release.jks` |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | alias ключа |
| `KEY_PASSWORD` | пароль ключа |

Если секреты не заданы, release APK собирается неподписанным, и в релиз автоматически попадает debug-подписанный APK (с суффиксом `-debug`). Его можно установить, но обновить поверх подписанного релиза нельзя.
